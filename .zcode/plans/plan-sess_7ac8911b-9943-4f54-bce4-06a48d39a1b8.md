### Fix 3 — Volume Licensing + Coupons auf B2B aktivieren

**Architekturentscheid:** Volume Licensing wird **Setting-gesteuert** aktiviert (wie Backend bereits über `pricing_strategy`-Setting). Coupons sind an Volume Licensing gekoppelt (`supportsCoupons()`-basiert, nicht mehr `isSrp`).

#### 3a. Frontend — `useLicensingMode` Setting-basiert
`useLicensingMode.ts` — statt hardcoded `brand === 'srp'`:
- Liest den Modus aus den License-Terms (`useLicenseTerms` bereits vorhanden, liefert Backend-Settings).
- Neuer Setting-Key `pricing_strategy` wird vom Backend via `/api/settings/license-terms` ausgeliefert (siehe 3c).
- Fallback auf `'scope_licensing'` wenn kein Setting.

#### 3b. Frontend — Volume-Licensing-Hooks und Cart
- `useVolumeLicensing.ts:109` — `if (!isSrp)` → `if (licensingMode !== 'volume_licensing')` (Hook muss `useLicensingMode` statt `useBrand` nutzen).
- `cartLogic.ts:45` — Brand-Branch durch LicensingMode-Branch ersetzen. `calculateTotalAmount` muss den Licensing-Modus kennen (entweder als Parameter oder der Aufrufer reicht ihn mit). Da `cartLogic` pure Funktionen sind: Parameter `useVolumePricing: boolean` statt `brand: Brand`.

#### 3c. Backend — `pricing_strategy` Setting via API ausliefern
`SettingsController::getLicenseTerms` (Zeile ~112-141) um den Key `pricing_strategy` ergänzen, damit das Frontend ihn lesen kann. Das Setting existiert bereits (wird von `AppServiceProvider:52-64` gelesen), es muss nur in der API-Antwort auftauchen.

#### 3d. Coupon-Frontend — an Licensing-Modus koppeln statt an Brand
- `CouponInput.tsx:39` — `if (!isSrp) return null` → `if (licensingMode !== 'volume_licensing') return null`
- `Sidebar.tsx:86` — Coupon-Admin-Eintrag: `{isAdmin && isSrp}` → `{isAdmin && licensingMode === 'volume_licensing'}` (Hook im Sidebar verfügbar machen)
- `ManagementCouponsView.tsx:67,85` — `if (!isSrp)` → licensingMode-Check
- `ManagementGalleryView.tsx` / `ManagementMetaGalleryView.tsx` — Coupon-Tabs: `isSrp` → licensingMode

#### 3e. Backend — Coupon-Hard-Gate entfernen
`CouponController.php:332-334` — Block entfernen:
```php
// ENTFERNEN:
if ($brand->value !== Brand::SRP->value) {
    return response()->json(['valid' => false, 'error' => 'Coupons are only available on buy.reisinger.pictures.']);
}
```
Stattdessen über `PricingStrategy::supportsCoupons()` steuern (der Aufruf `CheckoutService::resolveCoupon` prüft bereits `supportsCoupons()` bei `:57`).

#### 3f. CouponValidation-Test
PHPUnit: der bestehende Coupon-Test (falls vorhanden) muss auf B2B angepasst werden. Neuer Test: `test_coupon_works_on_b2b_with_volume_licensing` + `test_coupon_rejected_on_b2b_with_scope_licensing`.

**Tests:** Vitest (`cartLogic`, `useVolumeLicensing` mit licensingMode statt brand), PHPUnit (CouponController ohne Hard-Gate, mit Volume-Licensing-Setting).

### Fix 4 — CRM-Altersprüfung: Mindestalter 16 + optional

Birthdate ist bereits überall `nullable` (optional). Die einzige Änderung:

`CustomerController.php:43,64` — Validierungsregel:
```php
// VORHER:
'birthdate' => 'nullable|date|before:today|before:-10 years',
// NACHHER:
'birthdate' => 'nullable|date|before:today|before:-16 years',
```

`AgeHelper`-Display im Vertrag bleibt unverändert optional (zeigt nur, wenn birthdate gesetzt).

**Tests:** PHPUnit CustomerControllerTest erweitern: `test_birthdate_validates_minimum_age_16` (15-jährig → 422, 16-jährig → success, leer → success).
